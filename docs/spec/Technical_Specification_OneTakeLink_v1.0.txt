1. НАЗНАЧЕНИЕ ПРОЕКТА

Разработать бесплатное настольное приложение для Windows под названием OneTakeLink, предназначенное для домашней видеосъёмки исполнения на электрогитаре с использованием камеры iPhone 14 (и совместимых устройств).

Приложение должно объединять в одном компактном интерфейсе:
- получение видеопотока с iPhone через адаптированный и интегрированный модуль на базе исходного кода LensLink;
- мониторинг изображения перед записью;
- запись видеодублей на компьютер;
- управление библиотекой записей;
- кадрирование исходного видео под разные форматы;
- подготовку и экспорт роликов для социальных сетей, в первую очередь Instagram.

Это не полноценный видеоредактор и не программа для монтажа сложных многодорожечных проектов. Основной сценарий — установить телефон, проверить кадр, записать несколько дублей, выбрать удачный, при необходимости кадрировать и экспортировать.

2. ОСНОВНЫЕ ПРИНЦИПЫ И ОГРАНИЧЕНИЯ

2.1. Бесплатность
Приложение должно быть полностью бесплатным:
- без рекламы;
- без подписок и платных функций;
- без водяных знаков;
- без регистрации;
- без обязательного подключения к интернету;
- без искусственных ограничений длительности или количества записей.

Записи, настройки и данные библиотеки хранятся локально на компьютере пользователя. Количество записей ограничивается только доступным дисковым пространством и файловой системой.

2.2. Платформы
- Windows 10 x64.
- Windows 11 x64.

2.3. Основной режим видео
- Целевое разрешение: 1920×1080.
- Целевая частота кадров: 60 FPS.
- Основной контейнер записи и экспорта: MP4.
- Основной видеокодек: H.264/AVC.
- Дополнительный кодек при наличии поддержки: H.265/HEVC.
- Звук не нужен: приложение не должно захватывать микрофон, системный звук или записывать аудиодорожку.

2.4. Локальная работа
Основные функции должны работать без интернета. Интернет не должен быть необходим для записи, просмотра, управления файлами или экспорта.

3. ПОДКЛЮЧЕНИЕ КАМЕРЫ: ИНТЕГРАЦИЯ LENSLINK

3.1. Общая концепция
Вместо использования сторонних виртуальных камер приложение OneTakeLink использует адаптированный и переписанный под нужды проекта исходный код открытого проекта LensLink (https://github.com/MyNamesEMurray/LensLink).

LensLink изначально состоит из двух частей:
- iOS-приложения (LensLink Camera) — доступно в App Store;
- OBS-плагина, который подключается к телефону, декодирует поток и отдаёт кадры как источник в OBS Studio.

Важное уточнение:
- iOS-приложение мы не разрабатываем и не модифицируем.
- На iPhone используется готовое официальное приложение LensLink Camera из App Store (или TestFlight при необходимости).
- Вся адаптация и переписывание исходного кода касаются только Windows-части (логики OBS-плагина): протокола, транспорта, декодирования и интеграции в собственный пайплайн OneTakeLink.

3.2. Требования к переработке исходного кода LensLink (только Windows-часть)

Обязательные задачи по адаптации:

3.2.1. Удаление зависимости от OBS
- Полностью убрать использование libobs, obs_source, obs_data и связанных API.
- Переписать слой вывода кадров так, чтобы декодированные кадры (YUV/RGB) передавались напрямую во внутренний пайплайн OneTakeLink (Preview Layer и Recording Layer).
- Заменить систему свойств OBS на собственную систему настроек приложения.

3.2.2. Протокол и транспорт
- Сохранить и при необходимости доработать существующий wire-протокол LensLink (HELLO, VIDEO_CONFIG, поток Annex-B H.264/HEVC), чтобы он оставался совместимым с официальным iOS-приложением из App Store.
- Реализовать поддержку подключения:
  - по Wi-Fi (TCP, обнаружение через mDNS/Bonjour или ручной ввод IP);
  - по USB через usbmuxd / Apple Mobile Device Service (требуется наличие iTunes или Apple Devices на Windows).
- Обеспечить надёжное переподключение при временной потере связи.
- Реализовать обработку изменения параметров потока (разрешение, FPS, кодек) без аварийного завершения.

3.2.3. Декодирование
- Использовать FFmpeg (libavcodec) для декодирования H.264/HEVC.
- Приоритетно использовать аппаратное декодирование (D3D11VA / DXVA2 на Windows).
- Обеспечить низкую задержку и минимальное количество копирований буферов.
- Корректно обрабатывать ключевые кадры, SPS/PPS и смену параметров потока.

3.2.4. iOS-приложение
- Используется готовое официальное приложение LensLink Camera из App Store.
- Разработка, модификация или распространение собственной версии iOS-приложения не входит в задачи проекта.
- Приложение OneTakeLink должно корректно работать с актуальной версией LensLink Camera из App Store.
- Пользователь самостоятельно устанавливает LensLink Camera на iPhone и запускает поток.

3.2.5. Интеграция в архитектуру OneTakeLink
Модуль на базе LensLink должен быть оформлен как отдельный Camera/Input Layer:
- обнаружение доступных устройств (телефоны по Wi-Fi и USB);
- установка соединения с запущенным приложением LensLink Camera;
- получение и декодирование видеопотока;
- передача кадров и метаданных (фактическое разрешение, FPS, состояние устройства при наличии) в Preview и Recording слои;
- обработка отключения и переподключения;
- предоставление API для управления параметрами камеры (в пределах того, что поддерживает протокол и официальное iOS-приложение).

Не допускается жёсткая зависимость остальной логики приложения (запись, библиотека, экспорт, UI) от внутренних деталей реализации модуля LensLink. Это позволит в будущем заменить или дополнить источник видео.

3.3. Требования к режиму работы
- Целевой режим: 1920×1080 при 60 FPS.
- Приложение должно отображать фактические разрешение и FPS получаемого потока, а не только выбранные или заявленные значения.
- При недоступности источника должно отображаться понятное сообщение с возможной причиной и рекомендациями (проверить запуск приложения LensLink Camera на iPhone, USB-кабель, iTunes/Apple Devices, сеть, firewall и т.д.).
- Поддержка длительной стабильной передачи без систематических пропусков кадров на подходящем оборудовании.

3.4. Поведение при проблемах подключения
- Если приложение LensLink Camera на iPhone не запущено, устройство недоступно или соединение потеряно, OneTakeLink не должен аварийно завершаться.
- Пользователь должен видеть статус источника и инструкцию по восстановлению.
- После восстановления источника приложение должно позволять повторно выбрать устройство и продолжить работу.
- Во время записи потеря источника должна обрабатываться безопасно: уже полученный фрагмент по возможности сохраняется, а пользователь получает уведомление о прерывании.

3.5. Известные особенности и статус
LensLink является открытым проектом (GPL-2.0-or-later). При адаптации исходного кода Windows-части необходимо соблюдать условия лицензии (сохранение уведомлений об авторских правах, предоставление исходного кода производных работ при распространении и т.д.).

Целевой режим 1080p60 на iPhone 14 + официальный LensLink Camera + адаптированный Windows-модуль является приоритетным, но его достижение зависит от реальных возможностей устройства, версии iOS, качества USB/Wi-Fi соединения и реализации. Приложение обязано показывать фактические параметры потока.

4. ОСНОВНОЙ ИНТЕРФЕЙС

4.1. Общая структура
Интерфейс должен быть компактным, понятным и ориентированным на быстрый цикл «подключить — проверить — записать — выбрать дубль — экспортировать».

Предусмотреть два основных раздела:
- «Съёмка»;
- «Библиотека».

Основная рабочая область раздела «Съёмка» — крупное окно мониторинга камеры. Управление записью и основные параметры должны находиться рядом и не перекрывать важную часть изображения.

4.2. Статусная информация
Отображать:
- состояние подключения источника (LensLink);
- название/идентификатор выбранного устройства;
- фактическое разрешение входящего видеопотока;
- фактический FPS;
- состояние записи;
- длительность текущей записи;
- свободное место на диске;
- при возможности — предупреждения о перегреве телефона или других ограничениях источника.

4.3. Управление
Основные элементы:
- выбор источника видеосигнала (устройство LensLink);
- кнопка REC;
- кнопка STOP;
- выбор папки хранения;
- переход в библиотеку;
- настройки изображения и кадрирования;
- включение/выключение направляющих;
- переход к настройкам экспорта.

Во время записи интерфейс должен оставаться отзывчивым. Нельзя блокировать приложение на время кодирования или записи файла.

4.4. Полноэкранный режим
Предусмотреть полноэкранный мониторинг камеры. В полноэкранном режиме элементы управления могут скрываться или становиться компактными, но пользователь должен иметь возможность быстро остановить запись и выйти из режима.

5. МОНИТОРИНГ И НАСТРОЙКИ КАМЕРЫ

5.1. Мониторинг
- Отображение изображения с минимально возможной задержкой.
- Сохранение пропорций исходного изображения.
- Режим вписывания кадра в окно без растяжения.
- Отображение выбранного соотношения сторон и области будущего кадрирования.
- Возможность временно отключать все направляющие.

5.2. Настройки камеры
Предусмотреть доступ к параметрам источника через адаптированный протокол LensLink (в пределах того, что поддерживает официальное iOS-приложение):
- фокус и блокировка автофокуса;
- экспозиция и блокировка автоэкспозиции;
- баланс белого;
- ISO и выдержка;
- выбор доступного объектива/камеры iPhone;
- фронтальная или основная камера;
- цифровой зум.

Если параметр не поддерживается источником, соответствующий элемент интерфейса должен быть недоступен или скрыт. Нельзя показывать фиктивные настройки, которые не влияют на изображение.

5.3. Композиционные направляющие
Предусмотреть:
- сетку третей;
- центральную вертикальную и горизонтальную направляющие;
- безопасные области кадра;
- рамку выбранного формата кадрирования;
- Instagram Guidelines / safe zones.

Направляющие являются только наложением на мониторинг и не должны попадать в записанное или экспортированное видео, если пользователь явно не запросил иное. В рамках текущего ТЗ они используются как вспомогательный overlay и в итоговый ролик не включаются.

5.4. Дополнительные инструменты
Как необязательные функции:
- zebra для контроля пересветов;
- гистограмма;
- индикация реального FPS;
- индикация свободного места;
- предупреждение о перегреве телефона, если источник предоставляет такие данные.

6. ЗАПИСЬ ВИДЕО

6.1. Основной сценарий
1. Пользователь устанавливает и запускает официальное приложение LensLink Camera из App Store на iPhone.
2. Устанавливает соединение с OneTakeLink (Wi-Fi или USB).
3. Выбирает устройство в приложении OneTakeLink.
4. Проверяет изображение и параметры потока.
5. Выбирает папку или проект для сохранения.
6. При необходимости настраивает кадрирование и направляющие.
7. Нажимает REC.
8. Нажимает STOP.
9. Запись автоматически появляется в библиотеке.

6.2. Параметры записи
- Целевой режим: 1920×1080, 60 FPS.
- Формат: MP4.
- Кодек по умолчанию: H.264.
- Запись без аудио и без пустой аудиодорожки.
- Настраиваемое качество/битрейт с разумным значением по умолчанию.
- По возможности — аппаратное кодирование.
- Стабильная длительная запись без зависания интерфейса.

6.3. Кодирование
Предусмотреть использование доступных аппаратных кодировщиков:
- Intel Quick Sync;
- NVIDIA NVENC;
- AMD AMF.

Если аппаратное кодирование недоступно или нестабильно, использовать программное кодирование. Приложение должно корректно сообщать об ошибке и не терять уже записанный материал при сбое кодировщика, насколько это технически возможно.

6.4. Надёжность записи
- Запись должна завершаться корректно при нажатии STOP.
- При неожиданном отключении источника или ошибке кодирования приложение должно попытаться сохранить уже полученный фрагмент.
- Предусмотреть механизм безопасного завершения/восстановления незавершённой записи после аварийного закрытия программы или отключения питания, насколько это возможно для выбранного контейнера и способа записи.
- Предупреждать о недостатке свободного места до начала записи.
- Контролировать доступное место во время записи.
- Не допускать повреждения ранее созданных файлов при ошибке новой записи.

6.5. Таймер и управление
Дополнительно предусмотреть:
- таймер начала записи на 3, 5 или 10 секунд;
- горячие клавиши: Space — REC/STOP; F11 — полноэкранный режим; Esc — выход из полноэкранного режима; Delete — удаление выбранного дубля с подтверждением; Ctrl+E — экспорт выбранного дубля.

7. КАДРИРОВАНИЕ

7.1. Режимы
Должны поддерживаться оба сценария:
- запись полного исходного кадра с последующим кадрированием при экспорте;
- кадрирование до записи, если это технически возможно без потери стабильности и с корректным отображением области захвата.

Основной оригинал не должен необратимо теряться из-за кадрирования. Если пользователь выбирает кадрирование до записи, поведение должно быть явно обозначено в интерфейсе.

7.2. Форматы кадра
Предусмотреть готовые соотношения сторон:
- 16:9 — горизонтальное видео;
- 9:16 — вертикальное видео;
- 4:5 — вертикальный формат ленты;
- 1:1 — квадрат;
- пользовательское соотношение сторон.

7.3. Правила кадрирования
- Не растягивать изображение.
- Сохранять исходные пропорции.
- Давать пользователю возможность перемещать область кадрирования.
- Показывать результат кадрирования в превью до экспорта.
- Предупреждать, если выбранный кроп заметно уменьшает эффективное разрешение.
- Не увеличивать изображение искусственно без явного решения пользователя.
- Предусмотреть сохранение положения и размера области кадрирования как параметров конкретной версии экспорта.

8. БИБЛИОТЕКА ДУБЛЕЙ

8.1. Общие требования
В приложении должен быть отдельный раздел «Библиотека», в котором отображаются все созданные записи.

8.2. Информация о каждом дубле
Для каждого файла отображать:
- миниатюру;
- имя;
- длительность;
- дату и время создания;
- размер файла;
- разрешение;
- частоту кадров, если она определена;
- формат/кодек, если доступно;
- отметку избранного.

8.3. Действия с дублями
Предусмотреть:
- встроенный просмотр видео;
- воспроизведение и паузу;
- переименование;
- удаление через приложение;
- массовое выделение и удаление;
- добавление/снятие избранного;
- сортировку по дате, имени, длительности и размеру;
- открытие файла во внешнем проигрывателе;
- открытие папки файла в Проводнике Windows.

Удаление должно сопровождаться подтверждением. Если возможно, предусмотреть перемещение в Корзину Windows вместо безвозвратного удаления.

8.4. Проекты и сессии
Предусмотреть организацию записей по проектам и съёмочным сессиям.

Пример структуры:
Projects/
  Project_Name/
    Session_2026-11-08/
      Take_001.mp4
      Take_002.mp4
      Take_003.mp4
    Exports/
      Take_001_Instagram_9x16.mp4

Пример автоматического имени: 2026-11-08_Project_Take_001.mp4

Пользователь должен иметь возможность выбрать папку хранения и изменить шаблон имени файла. Нельзя принудительно перемещать или переименовывать уже существующие пользовательские файлы без подтверждения.

9. ПРОСМОТР И ПОДГОТОВКА К ЭКСПОРТУ

Для выбранного дубля предусмотреть отдельный экран/панель подготовки:
- встроенный плеер;
- выбор соотношения сторон;
- настройка области кадрирования;
- просмотр результата;
- включение направляющих и safe zones;
- выбор параметров кодирования;
- запуск экспорта.

Направляющие Instagram и другие композиционные линии показываются только в интерфейсе и не должны записываться в итоговый файл.

10. ЭКСПОРТ

10.1. Форматы
- MP4 — основной формат.
- H.264/AVC — кодек по умолчанию.
- H.265/HEVC — дополнительный вариант при наличии поддержки и совместимости.
- SDR / Rec.709 — базовый целевой цветовой режим.
- Без аудиодорожки.

10.2. Параметры
Пользователь должен иметь возможность выбрать:
- разрешение;
- частоту кадров, если преобразование поддерживается;
- качество или битрейт;
- кодек H.264 или H.265;
- аппаратное или программное кодирование, если доступно;
- соотношение сторон;
- положение и масштаб кадрирования.

Предусмотреть разумный профиль экспорта для Instagram и возможность ручной настройки.

10.3. Сохранность оригинала
- Экспорт всегда создаёт отдельный файл.
- Исходная запись не перезаписывается.
- Один дубль может иметь несколько экспортированных версий с разными форматами.
- Имя и папка экспортируемого файла должны быть понятны пользователю.

10.4. Instagram Guidelines
В окне подготовки экспорта предусмотреть overlay с направляющими и безопасными зонами для интерфейса Instagram.
- Направляющие не включаются в итоговый ролик.
- Должна быть возможность включить и выключить overlay.
- Предусмотреть отдельные варианты направляющих для вертикального и горизонтального контента, если применимо.

12. ОБРАБОТКА ОШИБОК И УСТОЙЧИВОСТЬ

Приложение должно корректно обрабатывать:
- отсутствие запущенного приложения LensLink Camera на iPhone;
- отсутствие доступных устройств LensLink;
- отключение USB или Wi-Fi;
- потерю видеопотока;
- изменение доступного разрешения или FPS;
- недостаток свободного места;
- невозможность создать файл;
- ошибку кодировщика;
- аварийное завершение записи;
- повреждение или недоступность файла;
- отсутствие прав на выбранную папку.

Ошибки должны описываться понятным языком. По возможности указывать конкретное действие для восстановления. Приложение не должно завершаться аварийно из-за обычных ошибок источника или диска.

13. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

- Интерфейс остаётся отзывчивым во время записи и экспорта.
- Захват, запись, кодирование, просмотр библиотеки и интерфейс не должны блокировать главный поток приложения.
- Необходимо избегать ненужного копирования больших видеобуферов.
- Потребление ресурсов должно быть разумным для обычного современного Windows-ПК.
- Длительная запись должна работать стабильно.
- Приложение должно корректно обрабатывать закрытие окна и завершение работы Windows.
- Все пользовательские данные хранятся локально.
- Не собирать телеметрию и не отправлять пользовательские файлы или сведения о них в сеть.

14. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА

Рекомендуется разделить приложение на независимые модули:

1. Camera/Input Layer (адаптированный LensLink — только Windows-часть)
   - обнаружение устройств (Wi-Fi / USB);
   - установка и поддержание соединения по протоколу LensLink с официальным iOS-приложением;
   - декодирование H.264/HEVC (FFmpeg + аппаратное ускорение);
   - получение фактических параметров потока;
   - обработка отключения и переподключения;
   - управление параметрами камеры через протокол (в пределах поддержки официального приложения).

2. Preview Layer
   - отображение изображения;
   - масштабирование без искажения пропорций;
   - наложение сетки, рамок и safe zones;
   - отображение области кадрирования.

3. Recording Layer
   - запись видеопотока;
   - управление REC/STOP;
   - управление именами и путями;
   - контроль свободного места;
   - безопасное завершение и восстановление, где возможно.

4. Encoding/Export Layer
   - H.264/H.265;
   - аппаратное и программное кодирование;
   - кадрирование и масштабирование;
   - создание отдельных экспортных файлов.

5. Library Layer
   - индексирование записей;
   - миниатюры и метаданные;
   - сортировка и фильтрация;
   - переименование и удаление;
   - избранное и проекты/сессии.

6. UI Layer
   - разделы «Съёмка» и «Библиотека»;
   - настройки;
   - уведомления;
   - горячие клавиши.

Выбор конкретного языка программирования и UI-фреймворка остаётся техническим решением разработчика. Приоритеты: стабильная работа с видеозахватом и декодированием на Windows, аппаратное кодирование, современный интерфейс и удобная поддержка проекта. Рекомендуемые направления: C++/C# с использованием Media Foundation / DirectX / FFmpeg, либо современный кроссплатформенный стек с нативной поддержкой Windows.

15. ПРОИЗВОДИТЕЛЬНОСТЬ И КАЧЕСТВО

Целевые показатели:
- мониторинг 1920×1080 при 60 FPS при условии, что источник реально отдаёт такой поток;
- запись без систематических пропусков кадров на подходящем ПК;
- отсутствие заметного рассинхрона, поскольку аудио не используется;
- отсутствие растяжения или непредусмотренного изменения пропорций;
- отсутствие включения служебных overlay в итоговый файл;
- корректная запись длинных дублей;
- предсказуемое качество H.264 при выбранном пользователем битрейте/профиле.

Фактические показатели зависят от iPhone, версии официального приложения LensLink Camera, качества соединения (USB/Wi-Fi), Windows, драйверов и аппаратных возможностей ПК. Приложение должно показывать фактические параметры, а не обещать недостижимые значения.

17. КРИТЕРИИ ПРИЁМКИ

Приложение считается соответствующим базовым требованиям, если:

1. Запускается на целевой Windows-системе без обязательного интернета и регистрации.
2. Обнаруживает и подключается к устройству через адаптированный модуль LensLink при корректно запущенном официальном приложении LensLink Camera на iPhone.
3. Показывает изображение с камеры в окне мониторинга.
4. Показывает фактические разрешение и FPS.
5. Позволяет начать и остановить запись.
6. Создаёт корректный MP4 H.264 без аудиодорожки.
7. Сохраняет запись в выбранную пользователем папку.
8. Автоматически добавляет запись в библиотеку.
9. Позволяет воспроизвести, переименовать и удалить дубль.
10. Не завершает работу аварийно при отключении источника.
11. Поддерживает полный кадр и кадрирование.
12. Позволяет экспортировать отдельную копию, не изменяя оригинал.
13. Поддерживает основные форматы 16:9, 9:16, 4:5 и 1:1.
14. Показывает Instagram Guidelines поверх предпросмотра, не включая их в файл.
15. Остаётся отзывчивым во время записи.
16. Корректно предупреждает о недостатке места и ошибках записи.

Отдельный критерий подтверждения целевого режима:
- связка iPhone 14 + официальный LensLink Camera (App Store) + адаптированный Windows-модуль + USB/Wi-Fi + Windows 11 должна фактически передавать 1920×1080 при 60 FPS (или максимально близкий стабильный режим);
- режим должен быть проверен длительной записью, а не только кратковременным просмотром;
- необходимо проверить реальный FPS, пропуски кадров, стабильность соединения и нагрев телефона.

Если текущая реализация не обеспечивает 1080p60 на iPhone 14, это фиксируется как ограничение источника, а не маскируется программой. При этом архитектура приложения должна позволять использовать другой совместимый Windows video source в будущем.
